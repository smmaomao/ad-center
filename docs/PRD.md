## 一、文档目的与范围

### 1.1 文档目的

本文档定义短剧App自有广告投放管理系统的功能需求、业务流程和数据结构，作为产品设计、研发、测试的统一基线。

### 1.2 产品范围

- **包含：** 广告主管理、广告位管理、AI Agent控制台、实时监控看板
- **不包含：** 广告主侧的投放报表、广告素材自动生成、DSP对接

## 二、产品概述

### 2.1 产品定位

短剧App自有广告投放管理系统是一套面向运营人员的广告策略管理工具，用于管理App内所有广告位（激励视频、开屏、插屏、信息流）的填充策略，支持多Slots广告主（甲方客户）的流量分配、实时竞价、保底策略，并提供AI Agent辅助决策与全链路数据监控。

### 2.2 核心原则（V1.1 更新）

核心逻辑：系统的首要任务是"帮甲方花好预算、达成KPI"，在此基础上再追求平台自身收益最大化。这与传统ADX以eCPM为单一目标不同——本系统是以服务甲方为核心的托管式投放平台。

优先级顺序：

| 优先级 | 原则 | 说明 |
|--------|------|------|
| 第一优先级 | 甲方出价KPI达成 | 广告主设定的出价目标（CPI/CPA）是必须优先保证的考核指标 |
| 第二优先级 | 甲方每日预算控制 | 确保每个广告主的日预算按计划平滑消耗，避免过早耗尽或剩余过多 |
| 第三优先级 | 平台eCPM优化 | 在满足甲方KPI和预算的前提下，最大化平台的千次展示收益 |

### 2.3 核心能力

- **KPI优先的广告位预留：** 将App内高质量广告位优先预留给甲方Slots广告主，以甲方出价KPI为第一考核标准
- **预算平滑消耗控制：** 实时监控各广告主预算消耗进度，动态调整流量分配，确保预算按计划均匀消耗
- **动态调配：** 运营人员可实时调整广告曝光分配、出价和预算策略，所有配置变更秒级生效
- **AI Agent辅助：** 后期由AI Agent自动优化流量分配、出价和预算策略，以完成甲方KPI为首要目标
- **数据透明：** 提供实时看板，运营人员可随时查看各广告位填充状态、收益分布及AI决策日志

### 2.4 多客户端 App 隔离（V1.2 增补）

平台服务于多个客户端 App，App 间数据完全隔离：

| 项 | 规则 |
|----|------|
| App 接入 | 每个 App 在后台注册，分配独立 API Key（X-Api-Key 请求头） |
| 用户身份 | (app_id, deviceId) 复合标识——不同 App 的同名用户 ID 互不影响；App 身份由服务端从 API Key 推导，客户端不可自行声明 |
| 广告主 | **全局共享**：预算/KPI/素材跨 App 一份，投放哪些 App 由各 App 广告位的填充优先级决定 |
| 广告位 | 归属具体 App，各 App 独立配置填充策略与频控 |
| 数据看板 | 事件/指标/决策日志均带 App 维度，支持按 App 筛选 |

## 四、功能需求

### 4.1 广告主管理模块

#### FR-01：广告主列表

- **用户角色：** 广告运营
- **功能描述：** 展示所有已接入的Slots广告主信息，支持搜索、筛选和快速操作。

**列表字段：**

| 字段 | 说明 |
|------|------|
| 广告主名称 | 点击进入详情页 |
| 层级 | Tier1 / Tier2 / Tier3 |
| 日预算 | 美元 |
| 预算消耗进度 | 已消耗/日预算，进度条可视化 |
| 出价KPI达成率 | 实际达成CPI vs 目标CPI |
| 填充率 | 该广告主整体填充率 |
| 状态 | ●活跃 / ○暂停 / ⚠预算将尽 / ●预算耗尽 |

**操作功能：**

- 新增广告主
- 编辑广告主
- 暂停/激活广告主
- 删除（软删）

**筛选条件：**

- 按层级：Tier1 / Tier2 / Tier3
- 按状态：全部 / 活跃 / 暂停 / 预算耗尽
- 按KPI达成率：达标 / 未达标
- 按创建时间范围

**搜索：** 支持广告主名称模糊搜索

**业务规则：**

- 预算消耗 ≥ 日预算的95%时，状态自动变为"预算将尽"，系统发送预警通知
- 预算耗尽后状态自动变为"预算耗尽"，次日0点自动恢复
- KPI达成率 = 实际达成CPI / 目标CPI，≤1为达标，>1为未达标

#### FR-02：广告主详情/配置

- **用户角色：** 广告运营
- **功能描述：** 查看和编辑单个广告主的完整配置信息。

**顶部KPI卡片：**

| 指标 | 说明 |
|------|------|
| 日预算 | 广告主每日预算上限及消耗进度条 |
| 出价KPI达成率 | 实际CPI vs 目标CPI，绿色达标/红色未达标 |
| 填充率 | 该广告主在平台的整体填充率 |
| 平均eCPM | 该广告主在平台的整体平均eCPM及趋势 |

**基本信息配置：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 广告主ID | 文本（只读） | 是 | 系统自动生成 |
| 广告主名称 | 文本 | 是 | 用于识别 |
| 层级 | 下拉选择 | 是 | Tier1 / Tier2 / Tier3 |
| 保底流量占比 | 数字（0-100%） | 是 | 该广告主最低获得的曝光份额 |
| 合同周期 | 日期范围 | 否 | 合作起止时间 |
| 投放截止时间 | 日期时间 | 否 | 投放截止（V1.2）：过期后不参与决策，NULL=永续；与合同周期（商务概念）相互独立 |
| 对接人 | 文本 | 否 | 甲方联系人 |
| 状态 | 开关 | 是 | 活跃/暂停 |

**KPI与预算配置（核心）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 出价模式 | 下拉选择 | 是 | CPI / CPA / Revenue Share |
| 目标出价（KPI） | 数字 | 是 | 广告主承诺的出价目标，系统需优先达成 |
| 实际达成出价 | 数字（只读） | 是 | 系统自动计算，实时更新 |
| KPI达成率 | 百分比（只读） | 是 | 目标出价/实际达成出价 |
| 日预算上限 | 数字 | 是 | 美元，广告主每日最高消耗 |
| 预算消耗速度 | 下拉选择 | 否 | 匀速消耗 / 加速消耗 / 尽快消耗 |
| 投放时段 | 下拉选择 | 否 | 全天/自定义时段 |

**投放配置：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 目标受众 | 多选/文本 | 否 | 国家、年龄、性别等 |
| 频控窗口 | 多窗口配置 | 否 | 多窗口滑动频控（V1.2）：如 3小时最多3次 + 24小时最多10次，多档同时生效；全滑动窗口，无自然日重置 |

**素材管理：**

| 功能 | 说明 |
|------|------|
| 素材列表 | 展示已上传素材（缩略图、名称、方向、形态、状态、CTR、转化率） |
| 上传素材 | 支持视频（MP4）和图片（JPG/PNG），单个≤50MB |
| 素材形态 | 视频 / 图片 / 网页（H5），上传时选择；网页素材填 URL |
| 素材方向 | 竖屏 / 横屏 / 方形 / 不限，上传时选择；服务端下发全部方向，客户端按展示位置自选（短剧 App 以竖屏为主） |
| 素材状态 | 测试中 / 活跃 / 暂停 |
| 流量分配 | 支持手动设置各素材流量权重，或启用自动A/B测试 |
| 删除素材 | 仅可删除"暂停"状态的素材 |

**实时数据：** 展示该广告主今日的核心数据：曝光量、点击量、CTR、转化量、消耗金额、平均eCPM、KPI达成率趋势图。

**业务规则：**

- Tier1广告主保底占比不得低于30%
- 系统优先保证所有活跃广告主的KPI达成率≥100%
- 当多个广告主同时面临KPI未达成风险时，按Tier层级优先分配流量

**列表字段：**

#### FR-04：广告位详情/策略配置

- **用户角色：** 广告运营
- **功能描述：** 配置单个广告位的填充优先级和高级策略（核心功能）。

**顶部KPI卡片：** 日请求量、填充率、展示量、eCPM

**填充优先级配置（核心）：**

以表格形式展示所有可用的填充来源（各广告主 + MAX聚合）：

| 列 | 说明 | 交互 |
|----|------|------|
| 优先级 | P0, P1, P2... | 拖拽调整顺序 |
| 填充来源 | 广告主名称 / MAX聚合 | — |
| 层级 | Tier1/2/3（仅广告主） | — |
| 当前KPI达成率 | 百分比（仅广告主） | 只读，自动计算 |
| 预算消耗进度 | 进度条（仅广告主） | 只读，自动计算 |
| 状态 | 启用/停用 | 开关 |

**优先级排序逻辑（V1.1 更新）：**

系统自动计算每个广告主的投放优先级得分，得分越高排序越靠前：

```
投放优先级得分 = KPI达成紧急度 × 预算消耗进度 × 层级权重
```

| 因子 | 计算方式 | 说明 |
|------|----------|------|
| KPI达成紧急度 | 1 / (KPI达成率 + 0.01) | 达成率越低，紧急度越高 |
| 预算消耗进度 | 已消耗 / 日预算 | 进度越慢，需要加速消耗 |
| 层级权重 | Tier1=1.5, Tier2=1.2, Tier3=1.0 | 高Tier优先保障 |

系统按得分从高到低排序，得分越高获得流量的优先级越高。

**业务规则：**

- 所有Tier1/2/3广告主保底占比之和 ≤ 100%
- 系统优先保障KPI达成率<100%的广告主获得更多流量
- 当广告主KPI达成率>120%时，系统自动降低其流量分配，将资源让给未达标的广告主

**高级策略配置：**

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 频控上限 | 8次/人/天 | 滑动24小时窗口内单用户可观看该广告位最大次数 |
| 观看间隔 | 20分钟 | 两次展示间最短间隔 |
| 疲劳度窗口 | 3次 | 连续N次不重复展示同一广告主 |
| 保底机制 | 启用 | 启用/停用分层保底 |

**频控体系（V1.2 更新）：** 两级配置，检查时任一策略不过即跳过该广告主：

| 层级 | 配置位置 | 策略 |
|------|----------|------|
| 广告位级 | 本表（高级策略配置） | 滑动24h日频控 + 最小间隔 + 疲劳窗口 |
| 广告主级 | 广告主投放配置 | 多窗口滑动频控：多档窗口同时生效（如 3h/3 + 24h/10） |

所有时间窗均为**滑动窗口**（从当前时刻回溯，无自然日 0 点重置）；预算消耗的自然日重置独立于此，不受影响。

**AI Agent接管：**

- 提供"AI Agent接管"开关
- 开启后系统自动以"完成所有甲方KPI"为首要目标，优化流量分配
- 接管后仍可手动调整，但会标记"人工覆盖"

## 五、业务流程

### 5.1 广告请求决策流程（V1.1 更新）

1. **开始：** 用户触发广告请求
2. 客户端上报请求（用户端/广告位/广告位+创意/频次）
3. 后端获取广告/定位/填充方案/策略
4. **第1步：筛选活跃广告主**（根据状态过滤 → 根据模式过滤 → 计算广告主KPI状态）
5. KPI达成度 > 85%？
   - **是** → KPI达成率≥100%？
     - 是 → 标记为"达优保障"，优先级提升 ×1.2
     - 否 → 标记为"正常保障"，优先级提升 ×1.2
   - **否** → 标记为"紧急保障"，优先级降低 ×0.8
6. 计算优先级得分
7. 预算消耗速度 > 时间进度？（消耗偏慢）
   - **是** → 优先级得分 ×1.3，加速填充
   - **否** → 保持当前优先级
8. 应用Tier优先级配置（Tier1=1.5 / Tier2=1.2 / Tier3=1.0）
9. 计算最终优先级得分，按得分排序
10. 依次遍历广告主填充：
    - 是否有填充？
      - **是** → 该用户是否看过该广告主（疲劳度）？
        - 是 → 跳过，尝试下一广告主
        - 否 → 返回该广告主素材，流程结束
      - **否** → 还有填充来源？
        - 是 → 返回MAX聚合广告
        - 否 → 返回平台自有推广/兜底
11. 记录本次广告主KPI/状态/得分

### 5.2 预算平滑控制流程

1. **触发：** 每小时定时触发
2. 计算各广告主预期消耗进度（预期进度 = 当前时间 / 全天总时间）
3. 计算实际消耗进度（实际进度 = 已消耗 / 日预算）
4. **判断：实际进度 vs 预期进度**
   - 实际 < 预期 - 10%（消耗偏慢）→ 提升流量分配权重 ×1.3，加速消耗
   - 实际 > 预期 + 10%（消耗偏快）→ 降低流量分配权重 ×0.8，减速消耗
   - 偏差在 ±10% 内（正常）→ 保持当前权重
5. 记录调整日志
6. **判断：是否启用AI Agent？**
   - 是 → AI Agent自动执行调整
   - 否 → 发送建议给运营人员，人工确认后执行

### 5.3 广告主上线配置流程

1. 运营进入广告主管理
2. 新增/编辑广告主
3. 填写基本信息（名称/层级）
4. 设置KPI与预算（目标出价/日预算/消耗速度）
5. 上传广告素材
6. 保存广告主配置
7. 进入广告位管理
8. 选择目标广告位
9. 将该广告主添加至填充优先级列表
10. 系统自动计算当前KPI状态和优先级得分
11. 运营可手动调整优先级顺序
12. 保存配置
13. 配置实时生效，系统以完成甲方KPI为首要目标，自动分配流量

### 5.4 AI Agent接管流程

1. **起点：** 运营在广告位详情页点击AI Agent接管
2. 选择优化目标（KPI达成优先/预算平滑优先/eCPM优先）
3. 进入学习期（默认24小时）
4. Agent分析历史数据，识别KPI驱动因子
5. 运营查看模拟效果与KPI达成预测
6. **判断：效果符合预期？**
   - 否 → 调整优化目标/参数，重新进入学习期
   - 是 → 正式接管
7. Agent开始执行优化，以保障KPI为首要目标
8. 实时监控各广告主KPI
9. **判断：KPI达成率 < 85%？**
   - 是 → 自动提升该广告主流量权重（最高可调升2倍）
   - 否 → 进入下一判断
10. **判断：KPI达成率 > 120%？**
    - 是 → 自动降低该广告主流量权重（释放流量给未达标广告主）
    - 否 → 保持当前策略
11. 所有动作记录决策日志
12. 运营持续监控
13. **判断：需要人工干预？**
    - 否 → 返回"运营持续监控"继续循环
    - 是 → 暂停Agent / 人工覆盖决策
14. 记录干预原因

### 5.5 客户端批量拉取（V1.2 增补，2026-09-04）

App 可一次请求 N 条广告：`POST /v1/ad/req` 增加 `count` 参数（默认 1，上限 20）。

**决策结论（已与产品确认）：**

| 设计点 | 结论 |
|--------|------|
| 名额分配 | **得分定名额**：优先级得分（5.1 公式）决定谁入选。count < 候选数时取得分前 count 名；count ≥ 候选数时全员入选 |
| 响应内顺序 | **单价定顺序**：每轮内按出价/有效 eCPM 降序排列 |
| 轮次语义 | count ≥ 候选数时整轮下发（候选 5、count=10 → 2 整轮）；余数名额（count mod 候选数）给得分最高者 |
| 参排单元 | 广告主参排；同广告主多素材按权重/A-B 内部轮选，两轮可出不同素材 |
| 候选不足 | 只返回可用条数，**不补位**；客户端缺口自行走 MAX 兜底 |
| 跨请求行为 | 服务端不记录上次下发，不做跨请求轮换；重复请求返回相同结果（频控/预算变化除外） |
| 频控交互 | 返回条数 ≤ 该用户该广告位剩余额度（滑动24h）；同广告主在响应中的条目数 ≤ 其各滑动窗口剩余额度的最小值 |
| 预算交互 | 每条独立预扣、未曝光回滚；广告主预算仅够 1 次展示时，该广告主在本次响应中至多出现 1 次 |
| 保底约束 | 保底广告主在单次响应中的条目数 ≥ ceil(保底占比 × count)；未入选名单时强制替换名单中得分最低的非保底者 |

**决策流程：**

1. 筛选活跃候选（定向匹配 / 频控余量 / 预算余量）——同 5.1 第 1 步
2. 计算 KPI 分档与优先级得分——同 5.1 第 2~9 步
3. 名额分配：按得分排序取名单，保底份额按 ceil(占比 × count) 强制保证
4. 生成条目序列：整轮下发（轮内单价降序）+ 余数给得分最高者
5. 逐条物化：素材内选（权重/A-B）→ 频控 CheckAndIncr → 预算 TryDeduct；任一失败跳过该条
6. 返回 items[]，条数可能少于 count

> 示例：候选 5 个广告主 A~E（得分 A>B>C>D>E，单价 C>A>E>B>D），
> count=3 → 名单 {A,B,C}，响应顺序 C,A,B；
> count=10 → 名单 {A..E}，响应 C,A,E,B,D, C,A,E,B,D。
